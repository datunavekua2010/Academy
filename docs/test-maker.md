# Teacher Test Maker — implementation and release review

## What is built

The teacher workspace renders the Test Maker under `სასწავლო მხარდაჭერა` alongside classrooms. It uses `CURRICULUM`, the actual template registry and `generateQuestion`, not a parallel question bank. Grade, topic, unit, subtopic, difficulty, answer mode and generated-prompt search filters apply to real templates. Repeatable sections store independent curriculum selections, template IDs and quantities (up to 100 total questions). Generation produces a single combined test using the real template generator and distinct shown questions; it is atomic and reports failure if a bounded search cannot find enough. The same template can appear in multiple sections. Existing generated questions can be rerolled, removed, ordered and scored; duplicates are rejected unless explicitly allowed. A draft contains the complete generated question and its matching answer, not just a seed. The same frozen snapshot feeds both the student file and answer key. Reopening does not regenerate the question. The editor supports settings, duplicate, delete confirmation and PDF downloads after the question list.

To avoid representing an incomplete graphic as a printable problem, the available subset excludes interactive questions, all `visual`, clock, drawn picture and ordering data, image-like prompt segments, described pictures, some wording that implies a missing diagram/table, and unsupported font characters. This is a conservative heuristic, not a proof that every remaining template is semantically correct on paper; tutor review is still essential. The section selector checks a small sample of seeds, so it can omit templates whose printable variants were not found in that sample; generation also uses a bounded search and does not prove a template has no other variants. Some text-only exercises are omitted. Diagrams and interactive widgets are **not** implemented for PDF. A question whose contents are too tall for one page is rejected rather than clipped. Some arbitrary tutor-entered text or symbols may not exist in the bundled fonts and fail export with an explicit error. No independently verified solution steps are added. All tests remain drafts; no finalization lifecycle is implemented.

`pdf-lib` and `@pdf-lib/fontkit` generate actual independent A4 PDF files with embedded Noto Georgian, Latin, Math and Symbols fonts (OFL license alongside fonts). PDFs are prepared from the same frozen data and exposed as two direct download links; the editor does not embed PDF viewer frames or automatically trigger downloads. Editing the test invalidates the prepared files. A host that sandboxes the site without download permission can still block downloads. The student PDF does not include the answer-key section. Multiple-choice options naturally include the correct option, without identifying it. The answer key includes the frozen answer; no explanation is fabricated. Page numbers and conservative page-break checks are included.

## Access and persistence — not yet deployed

`supabase/migrations/202611240001_teacher_tests_review.sql` creates a private owner-associated test table and owner/update index. Direct table access is revoked even for authenticated users; RLS is enabled with no direct table policies. Three `SECURITY DEFINER` RPCs check `auth.uid()` and current teacher role, scope all reads/updates/deletes to the owner, and use a revision to reject stale edits. The save RPC validates length, types, points, section quantities and each exercise's template and curriculum identity against the existing `exercise_templates` table. Sections and default points are optional for backward compatibility with older drafts; generated questions and their order remain frozen separately. The migration is still review-only and has not been applied. The editor uses no client-provided tutor identity to establish database authorization.

**Important integrity limitation:** the SQL validates the template identity and shape, but it does not execute the JavaScript generator or independently prove that client-supplied question text/answers are mathematically correct. An authorized tutor calling the RPC directly can change their own snapshot. The browser validates shape and compatibility, but the content should not be treated as server-verified. Trusted versioned generation and independent answer validation would be required for that guarantee. Reopening also depends on the referenced template still existing in the client registry; versioning/migration policy is needed for removed templates. Offset-paginated lists can change while loading.

The project currently has `TEST_ACCOUNT_MODE = true`, suppressing Supabase and real teacher sessions. The public teacher preview now exposes the same exercise editor and actual PDF downloads without authentication. It does not save drafts: its state is temporary and disappears on leaving or reloading the page, and it must not be used for private information. Draft save and retrieval are shown only for a connected tutor. The migration is **review only and has not been applied**; neither real session setup nor real Supabase persistence has been exercised. Do not enable authentication or apply the migration to production without authorization. Before rollout, review ownership/RLS, payload integrity, retention and generator versioning; apply on an isolated test project, configure existing `VITE_SUPABASE_URL` and `VITE_SUPABASE_PUBLISHABLE_KEY`, establish an approved teacher session, and run real PostgREST, multi-user, concurrency, accessibility and PDF integration tests. Do not use service-role keys in browser code.

Run `node scripts/test-teacher-test-policy.mjs` for local PGlite policy tests and `npx vitest run tests/test-maker-data.test.ts tests/test-maker-ui.test.tsx tests/test-maker-preview.test.tsx tests/test-maker-sections.test.tsx` for generator/PDF/UI tests. Local SQL and mocked-client UI tests do not establish real Supabase persistence across sessions. PDF downloads should be inspected in the browsers and printers the academy supports.
